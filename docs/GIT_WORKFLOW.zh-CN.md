# 日常提交代码

`commit` 是把改动记录到本机 Git 历史，`push` 是把本机提交上传到 GitHub。脚本默认依次完成两者。

## 双击提交

1. 修改并保存代码，完成适当验证。
2. 双击仓库根目录的 `commit.bat`。
3. 查看窗口列出的改动，输入本次提交说明并回车，例如“修复卫星地图切换”。提交说明为空时会取消，不会新增暂存内容。
4. 等待成功提示。需要登录 GitHub 时，按 Git 的凭据管理器提示完成认证。

脚本提交当前分支中所有未被忽略的改动，包括新增文件、已修改文件和删除操作。只想提交部分文件时，请使用 Git 命令或图形工具自行选择，不要直接运行默认脚本。

## PowerShell 用法

在仓库根目录执行：

```powershell
# 提交到本机，然后上传 GitHub。
./scripts/publish-github.ps1 -Message "修复卫星地图切换"

# 只创建本机提交，不联网、不上传。
./scripts/publish-github.ps1 -CommitOnly -Message "调整路线设置布局"

# 只预览，不暂存、不提交、不上传。
./scripts/publish-github.ps1 -DryRun
```

也可在终端运行 `./commit.bat -CommitOnly`，然后按提示输入说明。

默认沿用当前分支。只有需要明确指定分支时才使用 `-Branch`，例如 `-Branch main`；脚本不会自动切换已有提交的分支。

## 常见情况

- **没有新改动**：不会创建空提交；默认模式仍可上传之前只保存在本机的提交。
- **Push 失败**：本机已经成功创建的 commit 不会丢失。处理网络或认证问题后，可再次运行脚本；没有新改动时不会重复 commit。
- **GitHub 比本机更新或历史不一致**：脚本会停止，先用 Git 工具处理同步与冲突，再重试。脚本不会强制推送或自动合并不相关的历史。
- **缺少作者信息**：首次需要时输入 Git 作者名称和邮箱，只写入本仓库配置。
- **找不到 Git**：安装 Git for Windows，或通过 `-GitPath` 指定 `git.exe`。

`releases/`、构建产物和本机凭据文件不会作为普通未跟踪文件加入提交。脚本还会检查已跟踪文件，发现受限路径时停止。请仍然留意源码中是否误填了真实 Key；文件路径检查不等于完整的敏感信息扫描。
